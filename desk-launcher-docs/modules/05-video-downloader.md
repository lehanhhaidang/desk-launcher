# MODULE: VIDEO DOWNLOADER

## OVERVIEW
The Video Downloader module (internally "Media Toolbox") is a Tauri plugin + React window that combines three local-media workflows: a URL-driven downloader (Capture) that drives the bundled `yt-dlp.exe` sidecar with `ffmpeg.exe` for muxing/audio extraction, a batch image processor (convert / resize / crop / compress) that runs in-process via the Rust `image` crate, and a local video processor (convert / compress / trim / extract-audio) that shells out to the `ffmpeg.exe` sidecar. Each workflow owns its own in-memory task table keyed by a UUID `task_id`, streams progress over a dedicated Tauri window event, and feeds a unified zustand Queue store in the frontend. The crate is named `tauri-plugin-video-downloader` but the plugin identifier registered with Tauri is `video-downloader`.

---

## KEY FEATURES
- **URL capture (yt-dlp)**: Fetch metadata (`video_info`), pick a video/audio format, download as MP4 (best-video+bestaudio merge) or MP3 (audio extraction) with live byte/speed/ETA progress, then Save-As via dialog and clean up the temp file.
- **Local video processing (ffmpeg)**: Probe local files (resolution/duration/codecs/bitrate from ffmpeg stderr), then Convert (stream copy), Compress (libx264 + CRF presets), Trim (`-ss`/`-to` copy), or Extract Audio (mp3/m4a/wav) — one ffmpeg child per task, progress derived from `-progress pipe:1` `out_time_ms`.
- **Batch image processing (image crate, no sidecar)**: Probe dimensions/format, optional per-image crop, resize (with aspect-ratio preservation), output to PNG/JPEG/WebP with a configurable filename pattern; runs in a worker thread with cooperative cancellation.
- **Unified Queue**: A shared zustand `job-store` aggregates Capture/Image/Video jobs into one timeline (Active / History) with per-kind cancel, reveal-in-explorer, and "clear finished".
- **Platform detection**: URL pattern matching for YouTube, Bilibili, TikTok, X/Twitter, Facebook, Instagram, Twitch (download support is actually whatever yt-dlp can handle).
- **Per-feature isolation**: Three separate state tables and three event channels keep an in-flight job in one tab alive (via `forceMount`) while the user works in another.
- **Appearance**: themeable via the shared `@desk-launcher/theme` engine — an `<AppearanceButton>` in the toolbox header; per-app `appId` `video-downloader`. See [07-shared-infra](./07-shared-infra.md).

## API ENDPOINTS (Tauri commands, invoked as `plugin:video-downloader|<command>`)

### Download (capture)
| Command | Params | Description |
|---|---|---|
| `video_info` | `url: String` | Runs `yt-dlp --dump-single-json --no-warnings --no-download <url>`; parses JSON into `VideoInfo` (title, thumbnail, duration, channel, view_count, upload_date, sorted `video_formats` by tbr and `audio_formats` by abr). Returns `VideoInfo`. |
| `video_download_start` | `args: { url, format_id, output_type }` (`output_type` = "mp4"\|"mp3") | Generates a `task_id`, computes output template `<downloads>/<task_id>.%(ext)s`, builds yt-dlp args (`-f <fmt>+bestaudio[ext=m4a]/best` + `--merge-output-format mp4`, or the format id + `--extract-audio --audio-format mp3`), spawns the sidecar, stores the child in `CaptureState`, and spawns a tokio task that parses progress lines and emits `video-progress`. Returns `task_id` immediately. |
| `video_download_cancel` | `task_id: String` | Marks the handle `cancelled` and kills the yt-dlp child. |
| `video_download_read` | `task_id: String` | Locates the finished file (`find_output_file`) and returns its raw bytes (`Vec<u8>`) — used by the frontend Save-As flow. |
| `video_download_cleanup` | `task_id: String` | Removes the task from state and deletes the temp output file. |

### Video processing
| Command | Params | Description |
|---|---|---|
| `media_video_probe` | `paths: Vec<String>` | Runs `ffmpeg -hide_banner -i <path>` per file and parses stderr → `VideoFileProbe` (width, height, duration, fps, vcodec, acodec, bitrate, size, ok/error). Returns `Vec<VideoFileProbe>`. |
| `media_video_process_start` | `args: { path, settings }` | Probes for duration, plans ffmpeg args by `action` (Convert/Compress/ExtractAudio/Trim), spawns one ffmpeg child with `-progress pipe:1`, stores it in `VideoState`, and runs a progress loop emitting `media-video-progress`. Returns `task_id`. |
| `media_video_process_cancel` | `task_id: String` | Marks `cancelled`, kills the ffmpeg child (partial output deleted on Terminated). |
| `media_video_process_cleanup` | `task_id: String` | Removes the task and deletes its `videos/<task_id>/` output directory. |

### Image processing
| Command | Params | Description |
|---|---|---|
| `media_image_probe` | `paths: Vec<String>` | Opens each file with the `image` crate, returns `ImageProbeResult` (width, height, format label, size, ok/error). Synchronous, no sidecar. |
| `media_image_read_bytes` | `path: String` | Returns raw file bytes (`Vec<u8>`) so the frontend can build a blob URL for the crop editor (no decode in Rust). |
| `media_image_process_start` | `args: { files: [{ path, crop? }], output: ImageOutputSettings }` | Validates settings, creates `images/<task_id>/`, spawns a worker thread that decodes → optional crop → resize → encode (PNG/JPEG/WebP) per file, emitting `media-image-progress`. Returns `task_id`. |
| `media_image_process_cancel` | `task_id: String` | Sets the atomic cancel flag (checked between files). |
| `media_image_process_cleanup` | `task_id: String` | Removes the task and deletes its `images/<task_id>/` output directory. |

## EVENTS (Rust → frontend)
| Event name | Payload | Emitted when |
|---|---|---|
| `video-progress` | `DownloadProgress { task_id, status ("pending"\|"downloading"\|"processing"\|"completed"\|"failed"\|"cancelled"), progress, speed, eta, file_size, filename?, filepath?, error? }` | Each yt-dlp progress line during download, and once on terminal (Terminated) with completed/failed/cancelled + resolved filepath. |
| `media-video-progress` | `VideoProcessProgress { task_id, status ("running"\|"completed"\|"failed"\|"cancelled"), progress, speed?, eta?, message?, output_path?, output_name?, error? }` | On each ffmpeg `out_time_ms` update (status "running") and once on Terminated (completed with output_path, failed, or cancelled). |
| `media-image-progress` | `ImageBatchProgress { task_id, status ("running"\|"completed"\|"failed"\|"cancelled"), total, done, failed, current_file?, message?, output_dir?, error? }` | Before each file (running, with `current_file`) and once when the batch finishes/cancels (with `output_dir`). |

## DATABASE / STORAGE
No SQLite — there is no persistent database. Outputs are written to per-feature temp directories under `<launcher_data>/modules/video-downloader/` (resolved by `launcher_paths::module_data_dir`, i.e. `APPDATA/io.desklauncher/modules/video-downloader/`): `downloads/<task_id>.{mp4|mp3}` for capture, `videos/<task_id>/<name>-<suffix>.<ext>` for video processing, and `images/<task_id>/<pattern>.<ext>` for image batches. Job state is purely in-memory: three `Mutex<HashMap<String, Handle>>` tables in `state.rs` on the Rust side, and an in-memory zustand `job-store` on the frontend side (not persisted across window reloads). The sidecar binaries live in `apps/launcher/src-tauri/binaries/` and are gitignored.

## WORKFLOW

### Download a URL
1. User pastes a URL → `UrlInput` triggers `use-video-info` → `video_info` returns `VideoInfo` with sorted format lists.
2. User toggles MP4/MP3 (`FormatSelector`) and picks a quality/format id (`QualitySelector`).
3. `DownloadButton` → `CaptureTab.handleStartDownload` → `startDownload` invokes `video_download_start` (returns `task_id`, upserts a job).
4. Backend spawns yt-dlp, emits `video-progress` per line (status `downloading` with speed/eta); the frontend mirrors progress into the job store.
5. On terminal `completed`, the event carries `filepath`/`filename`. User clicks Save → dialog `save`, `video_download_read` returns bytes, `fs.writeFile` writes to the chosen path, then `video_download_cleanup` runs ~5s later to delete the temp file.
6. Cancel → `AbortController` + `video_download_cancel` kills the child and patches the job to `cancelled`.

### Process local media (video/image)
1. User drops files or picks them via the dialog → `addFiles` → `media_video_probe` / `media_image_probe` populates the entry list with metadata.
2. User configures settings (video: action + container/audio/compression/trim; image: format/quality/resize/naming + optional per-image crop via `CropEditorDialog`, which reads bytes through `media_image_read_bytes`).
3. Start → `media_video_process_start` (one ffmpeg child) or `media_image_process_start` (worker thread) returns `task_id` and upserts a job.
4. Progress streams on `media-video-progress` (from `out_time_ms`) or `media-image-progress` (per file done/total); the hook patches the job store.
5. On `completed`, the payload carries `output_path` (video) or `output_dir` (images). Queue rows can reveal the output in Explorer.
6. Cancel → `media_video_process_cancel` (kills ffmpeg, deletes partial) or `media_image_process_cancel` (atomic flag). `*_cleanup` deletes the task output directory when no longer needed.

## TRIGGERS & SIDE EFFECTS (hidden flows)

### Inbound (what invokes this module)
- The launcher host spawns the `video-downloader` window (HTML shim at `apps/launcher/modules-pages/video-downloader/main.tsx`) → renders `MediaToolbox`.
- Capture tab actions (fetch / download / save / cancel) → `capture.rs::{video_info, video_download_start, video_download_read, video_download_cancel, video_download_cleanup}`.
- Videos tab actions (add/probe / start / cancel / clear) → `video.rs::{media_video_probe, media_video_process_start, media_video_process_cancel, media_video_process_cleanup}`.
- Images tab actions (add/probe / crop-read / start / cancel / clear) → `image.rs::{media_image_probe, media_image_read_bytes, media_image_process_start, media_image_process_cancel, media_image_process_cleanup}`.
- Queue tab cancel (per kind) → `cancelByKind` re-uses the per-feature cancel commands above.

### Outbound (what this module sets off)
- **Spawns `yt-dlp.exe` sidecar** (download + metadata) → `capture.rs::{video_info, video_download_start}`. yt-dlp internally invokes the bundled ffmpeg for MP4 merge / MP3 extraction.
- **Spawns `ffmpeg.exe` sidecar** (probe + processing) → `video.rs::{single_probe/probe_one, media_video_process_start}`.
- **Spawns a worker `std::thread`** for image batches (in-process, `image` crate, no sidecar) → `image.rs::media_image_process_start` → `process_batch`.
- **Emits Tauri window events**: `video-progress`, `media-video-progress`, `media-image-progress` → `capture.rs`, `video.rs::emit`, `image.rs::emit_progress`.
- **Writes temp/output files**: `downloads/<task_id>.{mp4|mp3}`, `videos/<task_id>/*`, `images/<task_id>/*` → `paths.rs` dirs; deletes them on cancel/cleanup. Save-As writes the chosen user path (`fs:allow-write-file` to `$HOME/**` / `$DOWNLOAD/**`).
- **Reveal in Explorer / open path** via `@tauri-apps/plugin-opener` → `shared/reveal.ts`, used by `QueueRow`.
- **Creates module data directories** on first use → `launcher_paths::module_data_dir` + `std::fs::create_dir_all` in `paths.rs`.

## NOTES / GOTCHAS
- **Sidecar naming**: Tauri resolves sidecars by base name (`yt-dlp`, `ffmpeg`) but the files on disk must carry the target-triple suffix `-x86_64-pc-windows-msvc.exe` (set in `ensure-sidecars.mjs`). The capability allows `binaries/yt-dlp` and `binaries/ffmpeg` with `sidecar:true`.
- **`SKIP_SIDECARS=1`** short-circuits `ensure-sidecars.mjs` (useful in CI / when binaries are provided manually). Binaries in `apps/launcher/src-tauri/binaries/` are gitignored.
- **Cancellation semantics differ per feature**: capture/video kill the OS child process and delete partial output on Terminated; images use a cooperative atomic flag checked between files (an in-progress file finishes before cancel takes effect).
- **Cleanup is explicit**: `*_cleanup` commands must be called to delete temp dirs/files; capture cleanup is deferred ~5s after Save so a user can retry. Nothing is auto-purged on window close.
- **WebP quality is ignored**: the `image` crate writes lossless WebP only, so the JPEG/WebP quality slider effectively applies to JPEG (`quality.clamp(10,100)`); JPEG output forces RGB8 (no alpha).
- **Probe relies on ffmpeg stderr**: `media_video_probe` runs `ffmpeg -i` with no output (exit code 1 is expected) and scrapes the header text — robust enough for common formats but text-parse based.
- **MP4 download format string** is hardcoded to `<format_id>+bestaudio[ext=m4a]/best` with `--merge-output-format mp4`; MP3 uses the chosen format id plus `--extract-audio --audio-format mp3`.
- A couple of error strings in `capture.rs` are bilingual (Vietnamese phrase about bundled binaries) — cosmetic only.
