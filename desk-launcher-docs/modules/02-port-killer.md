# MODULE: PORT KILLER

## OVERVIEW
Port Killer is a Tauri plugin + React bundle that lists every listening/established TCP and UDP socket on the host (with owning PID and process name), lets the user label/group ports and bulk-kill stuck processes with built-in protection against terminating critical Windows system processes. It also ships a full SSH Tunnel Manager UI, but the Rust tunnel commands are currently stubs (they return empty lists or error strings) pending a planned `russh` implementation.

---

## KEY FEATURES
- **Live port inspection**: `list_ports` enumerates IPv4/IPv6 TCP (`LISTEN`/`ESTABLISHED`) and UDP sockets via `netstat2`, resolving each PID to a process name via `sysinfo`, deduped by `(pid, port)` and sorted by port.
- **Process termination**: `kill_ports` kills a list of PIDs and returns a per-PID success/error report.
- **System-process safety guard**: a frontend allow/deny list (`port-safety.ts`) blocks killing ~30 critical Windows processes (svchost, lsass, csrss, explorer, …) and PIDs 0 & 4.
- **Labels, groups & profiles**: per-port labels/groups and named profiles persisted in browser `localStorage` (no backend persistence).
- **SSH Tunnel Manager (UI complete, backend stubbed)**: create/edit/start/stop/delete local-forward tunnels and pick SSH keys — all Rust commands currently no-op/error until `russh` is added.
- **Auto-refresh**: polls ports + tunnels every 3 seconds (toggleable).

## DATABASE
No persistent storage on the backend and no managed state — the Rust plugin is stateless. `list_ports`/`kill_ports` build a fresh `sysinfo::System` per call and hold nothing between invocations; tunnels have no in-memory map (commands are stubs). The only persistence is **browser `localStorage`** in the frontend under two keys: `port-killer-configs` (per-port labels/groups) and `port-killer-profiles` (named profiles). No SQLite, no files on disk.

---

## WORKFLOW
**Port scan → display → kill:** On mount (and every 3s while auto-refresh is on) `PortKiller.tsx` calls `fetchPorts()` → `list_ports`. Results are merged with localStorage labels/groups (`mergePorts`) and rendered in `PortTable`. The user selects rows (or clicks a row's skull). For a single kill, `checkProcessSafety` runs; system-critical processes raise a danger `WarningDialog` and are blocked, otherwise a confirm dialog leads to `doKill([pid])`. For a bulk kill, the Kill button opens `KillConfirmDialog`; on confirm, `checkBulkKillSafety` partitions PIDs — if any are system processes the user is shown which are blocked vs which will be killed — and the safe set is sent to `killPorts()` → `kill_ports`. Kill results render in a banner; ports + tunnels reload ~500ms later.

**SSH tunnel flow (UI only today):** The Tunnels tab loads `fetchTunnels()` → `list_tunnels` (always empty). Add/Edit opens `TunnelDialog`; submitting calls `createTunnel`/`updateTunnel`, and the start/stop/delete card buttons call the matching commands. Because every tunnel command is a Rust stub, create/update/start/stop currently reject with an error string and the dialog surfaces "SSH connection failed"; the list stays empty.

## TRIGGERS & SIDE EFFECTS (hidden flows)

### Inbound (what invokes this module)
- The launcher host opens the `port-killer` window (capability `apps/launcher/src-tauri/capabilities/port-killer.json`), which mounts `PortKiller.tsx`.
- Auto-refresh interval + Refresh button → `fetchPorts`/`fetchTunnels` → handled in `modules/port-killer/rust/src/lib.rs::list_ports()` / `list_tunnels()`.
- Kill (single/bulk) → `killPorts` → `modules/port-killer/rust/src/lib.rs::kill_ports()`.
- Tunnel add/edit/start/stop/delete and SSH-key picker → `create_tunnel`/`update_tunnel`/`start_tunnel`/`stop_tunnel`/`delete_tunnel`/`list_ssh_keys()` (all stubs).

### Outbound (what this module sets off)
- **Process termination:** `kill_ports()` calls `sysinfo` `Process::kill()`, which terminates the target OS process (on Windows, `TerminateProcess`). This is the module's only real external side effect and is irreversible.
- **Logging:** `log::info!` on plugin init and on each successful kill.
- **No events emitted, no child processes spawned, no `Command::new`** — grep confirms zero `emit`/`listen`/`Command::new`/`spawn` in the module. (Tunnel child processes will be spawned only once the `russh`/SSH implementation lands.)
- This module never calls other modules (modules are isolated).

## NOTES / GOTCHAS
- **SSH tunnels are not implemented.** All 7 tunnel/ssh commands in `lib.rs` are stubs returning empty vecs or Vietnamese error strings ("SSH tunnels chưa hỗ trợ — sẽ thêm bằng russh ở version sau"). The UI (`TunnelManager`/`TunnelDialog`) is fully built and will work once a `russh`-based backend is added. `TunnelDialog` treats a non-running result as a failure, so creates will always surface "Connection failed" today.
- **Safety list is frontend-only.** `kill_ports` in Rust will kill any PID it is given (subject to OS permissions). The system-process protection lives entirely in `port-safety.ts`, so it is advisory and could be bypassed by calling the command directly.
- **Windows-centric safety list.** `SYSTEM_PROCESS_NAMES` and `SYSTEM_PIDS {0,4}` are Windows process names — this guard is meaningless on other OSes.
- **`fetchSshKeys` is wired but backend returns nothing**, so the identity-file picker always reports "No SSH keys found in ~/.ssh/".
- **No backend persistence:** labels, groups, and profiles live only in this window's `localStorage`; clearing site data loses them.
- Killing a process can fail silently-ish: a missing process returns "process not found" and an access-denied kill returns "kill returned false (access denied?)" — both surface in the results banner.
